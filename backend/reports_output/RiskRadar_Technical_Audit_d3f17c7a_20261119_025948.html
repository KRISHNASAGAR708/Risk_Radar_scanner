IBM Cloud Object Storage Bucket is Publicly Accessible

Resource: fintech-raw-analytics-data (bucket)

Vulnerability Description:

The IBM Cloud Object Storage bucket has public read or write access granted via ACLs or Anonymous Public Access policies, allowing unauthorized parties on the internet to list, download, or tamper with stored objects.

Threat Rationale (Why Dangerous):

Public buckets are one of the most common causes of massive cloud data breaches, allowing unauthenticated attackers to harvest sensitive customer documents, proprietary databases, and internal credentials.

Recommended Remediation:

Revoke public ACL grants and enforce Public Access Prevention on the IBM Cloud Object Storage bucket.

ibmcloud cos bucket-acl-put --bucket fintech-raw-analytics-data --acl private
ibmcloud cos public-access-block-put --bucket fintech-raw-analytics-data --public-access-block-configuration '{"BlockPublicAcls": true, "IgnorePublicAcls": true, "BlockPublicPolicy": true, "RestrictPublicBuckets": true}'
Compliance:

IBM Cloud Object Storage Bucket Allows Permissive CORS Wildcard

Resource: fintech-raw-analytics-data (bucket)

Vulnerability Description:

Cross-Origin Resource Sharing (CORS) rules on the bucket allow wildcard origin ('*'), permitting cross-origin web requests from any domain on the internet.

Threat Rationale (Why Dangerous):

Malicious websites visited by an authenticated user can execute unauthorized cross-origin requests against the storage bucket to exfiltrate confidential data.

Recommended Remediation:

Restrict CORS AllowedOrigins to only explicitly trusted corporate and web domain names.

ibmcloud cos bucket-cors-put --bucket fintech-raw-analytics-data --cors-configuration '{"CORSRules": [{"AllowedOrigins": ["https://trusted.company.com"], "AllowedMethods": ["GET"], "AllowedHeaders": ["Authorization"]}]}'
Compliance:
CLD.9.5.1CLD.13.1.4

IBM Cloud Object Storage Bucket Does Not Use Customer-Managed Encryption (SSE-KP)

Resource: fintech-raw-analytics-data (bucket)

Vulnerability Description:

The bucket uses default provider-managed encryption keys instead of IBM Key Protect or Hyper Protect Crypto Services customer-managed root keys (SSE-KP).

Threat Rationale (Why Dangerous):

Customer-managed encryption ensures cryptographic erasure capabilities, compliance with key lifecycle management guidelines, and zero-trust data protection against provider insider threats.

Recommended Remediation:

Associate the bucket with an IBM Key Protect customer root key (CRK) for hardware-secured envelope encryption.

ibmcloud cos bucket-create --bucket fintech-raw-analytics-data --ibm-sse-kp-encryption-algorithm '256' --ibm-sse-kp-customer-root-key-crn

Vulnerability Description:

Security Group Allows Unrestricted Inbound SSH (Port 22)

Resource: sg-dmz-external-web (security_group)

Vulnerability Description:

An inbound firewall rule permits SSH (TCP port 22) connections from anywhere on the internet (0.0.0.0/0), exposing virtual server instances directly to brute-force attacks and zero-day remote exploit payloads.

Threat Rationale (Why Dangerous):

Automated threat botnets continuously scan IPv4 address space for open SSH services to launch dictionary credential attacks, key harvesting, and botnet enrollment.

Recommended Remediation:

Remove 0.0.0.0/0 inbound rules for port 22 and restrict SSH management exclusively to a dedicated VPN gateway, IBM Cloud Direct Link, or internal bastion host.

ibmcloud is security-group-rule-delete r006-sg-dmz-external  --force
ibmcloud is security-group-rule-add r006-sg-dmz-external inbound tcp --port-min 22 --port-max 22 --remote
Compliance:
